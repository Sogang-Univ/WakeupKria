# WakeupKria

> **음성으로 디바이스를 깨우고, 제스처로 카메라를 조작한다.**

**AMD Kria KV260 기반 온디바이스 음성·제스처 제어 시스템**

---

## 프로젝트 소개

**카메라를 만지지 않고 카메라를 조작한다.**

촬영 또는 검사 중인 카메라의 화면을 확대하거나 이동하려면 일반적으로 기기에 손을 대야 합니다.
하지만 작업자의 손이 물체나 공구를 잡고 있거나 장갑을 착용한 상황에서는 이러한 조작이 어렵습니다.

**WakeupKria**는 이러한 상황에서 카메라를 직접 조작하지 않고,

**웨이크워드 → 제스처 → 카메라 제어**

의 방식으로 화면을 제어하는 엣지 AI 시스템입니다.

### 핵심 아이디어

* 음성은 **"지금부터 명령하겠다"**는 웨이크 신호로 사용
* 실제 명령은 **손 제스처**로 전달
* 카메라 2대가 서로 다른 역할을 담당
* 모든 AI 연산은 **AMD Kria KV260 내부에서 처리**
* 하나의 DPU에서 **제스처 모델과 작업 모델을 시분할 방식으로 교체**

---

## 시스템 구성

두 대의 카메라는 서로 다른 역할을 담당합니다.

| 구성             | 역할                    |
| -------------- | --------------------- |
| **카메라 1**      | 사용자의 손을 인식하는 입력 장치    |
| **카메라 2**      | AI 판정 및 제어 대상         |
| **마이크**        | 웨이크워드 검출              |
| **DPU**        | 무거운 영상 AI 추론          |
| **Cortex-A53** | 음성 검출 및 시퀀스 기반 제스처 분류 |

### 동작 흐름

```text
                    ┌─────────────────┐
                    │     마이크      │
                    │   웨이크워드    │
                    └────────┬────────┘
                             │ wake
                             ▼
┌──────────────┐      ┌───────────────┐
│   카메라 1   │ ───▶ │  DPU Gesture  │
│   사용자 손  │      │     Model     │
└──────────────┘      └───────┬───────┘
                              │
                              ▼
                       제스처 시퀀스
                              │
                              ▼
                     ┌────────────────┐
                     │   Cortex-A53   │
                     │  동작 분류/상태 │
                     └───────┬────────┘
                             │
                    ┌────────┴────────┐
                    │                 │
                  팬/줌              open
                    │                 │
                    ▼                 ▼
             ┌─────────────┐   ┌─────────────┐
             │   카메라 2  │   │ DPU Task    │
             │ 화면 제어   │   │    Model    │
             └─────────────┘   └──────┬──────┘
                                      │
                                      ▼
                                  AI 판정
```

## 핵심 설계 — 단일 DPU 시분할

WakeupKria의 핵심은 **DPU가 하나뿐인 환경에서 여러 AI 모델을 공존시키는 것**입니다.

DPU에서 두 모델을 동시에 실행하지 않고 **모드에 따라 필요한 모델을 교체하여 사용**합니다. 발표기획서에서도 이를 `off / gesture / task`의 3모드로 정의하고 있습니다.

```text
                 wake
                  │
                  ▼
        ┌──────────────────┐
        │     gesture      │
        │  제스처 모델 실행  │
        └────────┬─────────┘
                 │ open
                 ▼
        ┌──────────────────┐
        │       task       │
        │  작업 모델 실행   │
        └────────┬─────────┘
                 │
                 │ wake
                 ▼
        ┌──────────────────┐
        │     gesture      │
        └──────────────────┘

        bye / close
              │
              ▼
        ┌──────────────────┐
        │       off        │
        │   DPU 모델 없음   │
        └──────────────────┘
```

### DPU 동작 모드

| 모드        | DPU 상태 | 실행 모델          | 제스처 |
| --------- | ------ | -------------- | --- |
| `off`     | 유휴     | 없음             | ❌   |
| `gesture` | 사용     | Gesture XModel | ✅   |
| `task`    | 사용     | Task XModel    | ❌   |

**중요한 점은 `task` 상태에서도 제스처 모델이 없다는 것입니다.**

따라서 `off`와 `task`에서는 손짓만으로 시스템을 다시 `gesture` 상태로 돌릴 수 없습니다.
이를 해결하기 위해 **CPU에서 계속 실행되는 웨이크워드가 전체 시스템의 복귀 경로** 역할을 합니다.

## 제스처 명령

현재 시스템은 다음과 같은 제스처 이벤트를 사용합니다.

| 제스처             | 동작         |
| --------------- | ---------- |
| `open`          | Task 모드 전환 |
| `bye` / `close` | 시스템 비활성화   |
| `left`          | 왼쪽 이동      |
| `right`         | 오른쪽 이동     |
| `up`            | 위쪽 이동      |
| `down`          | 아래쪽 이동     |
| `thumbs up`     | 확대         |
| `thumbs down`   | 축소         |
| `hi`            | 무동작        |

### 화면 제어

카메라는 물리적으로 움직이지 않고 **디지털 팬/줌** 방식으로 화면을 제어합니다.

```text
           Gesture
              │
       ┌──────┴──────┐
       ▼             ▼
     Pan            Zoom
  ← → ↑ ↓       확대 / 축소
       │             │
       └──────┬──────┘
              ▼
          Camera 2
```

또한 카메라 화면의 위치와 배율은 DPU 모드와 독립적으로 유지됩니다.

따라서 작업 모델을 실행한 뒤 다시 제스처 모드로 돌아와도 **이전에 보고 있던 화면 위치와 배율이 유지됩니다.**

## 현재 시연 — 재활용 분류

현재 프로젝트의 시연 도메인은 **재활용 분류**입니다.

```text
사용자
  │
  │ "Hey Kria"
  ▼
Wakeup
  │
  │ 제스처
  ▼
카메라 화면 확대 / 이동
  │
  │ open
  ▼
재활용품 AI 분류
  │
  ▼
판정 결과 확인
```

재활용 분류는 WakeupKria가 적용될 수 있는 여러 작업 환경 중 하나의 구현 사례입니다.

프로젝트의 기본 문제는 특정 분야가 아니라,

> **손을 사용할 수 없는 작업자가 화면을 직접 조작해야 하는 문제**

입니다.

따라서 현재는 재활용 분류를 구현하고, 향후에는 동일한 시스템 구조를 다른 작업 도메인으로 확장하는 것을 목표로 합니다. 발표기획서에서도 **문제 → 재활용 분류 시연 → 제조 결함 검사 확장**의 3단계 서사로 정리되어 있습니다.

## 확장 계획 — 제조 결함 검사

다음 확장 대상으로 **제조 결함 검사**를 고려하고 있습니다.

### 왜 제조 결함 검사인가?

* 작업자가 장갑이나 공구를 사용
* 검사 대상과 작업자가 고정된 위치에서 마주 보는 구조
* 폐쇄망 환경에서 온디바이스 AI가 유리
* 카메라를 고정한 상태에서 팬/줌 조작 필요
* 기존 하드웨어 구조를 그대로 활용 가능

즉, 현재의 카메라 배치와 제스처 기반 조작 구조를 크게 변경하지 않고 **Task 모델을 교체하는 방식으로 확장**할 수 있습니다.

```text
                WakeupKria 공통 시스템
                         │
             ┌───────────┴───────────┐
             │                       │
       Gesture Model            Wakeword
             │                       │
             └───────────┬───────────┘
                         │
                    Task Model
                         │
             ┌───────────┼───────────┐
             ▼           ▼           ▼
         재활용 분류   제조 결함    기타 검사
```

## 모델 통합 조건

새로운 AI 모델을 DPU에서 사용하기 위해 다음 조건을 만족해야 합니다.

1. DPU에서 지원하지 않는 연산을 지원 연산으로 변경
2. `vai_q_pytorch`를 통한 양자화
3. `vai_c_xir`를 통한 컴파일
4. **단일 DPU 서브그래프 생성**
5. 프레임 예산 내 DPU 실행 시간 측정

## 모델 교체 방식

모델을 단순히 활성화/비활성화하는 것이 아니라 **필요한 XModel을 DPU에 로드하는 방식**으로 동작합니다.

```python
def load_model(self, model_path):
    self.runner = None
    self.overlay.load_model(model_path)
    self.runner = self.overlay.runner
```

즉,

```text
Gesture Mode
     │
     │ load_model()
     ▼
gesture.xmodel
     │
     │ open
     ▼
load_model()
     │
     ▼
task.xmodel
```

비트스트림은 `Runner()` 생성 시 준비하고, 모드 전환 시 필요한 XModel을 교체합니다. 모델 교체 과정에서는 기존 runner를 먼저 해제해야 하며, 전환 중에는 추론이 일시적으로 중단됩니다.

또한 모드 전환 직후 기존 제스처가 다시 인식되는 문제를 방지하기 위해 **시퀀스 버퍼를 초기화하고 1초 쿨다운을 적용**합니다.

## 기술적 특징

### 1. 온디바이스 AI

모든 주요 연산을 **AMD Kria KV260**에서 처리합니다.

```text
Camera / Microphone
        │
        ▼
   AMD Kria KV260
   ┌──────────────────────┐
   │ FPGA        CPU      │
   │                      │
   │ DPU         A53      │
   │ │           │        │
   │ │           ├─ Wakeword
   │ │           └─ GRU
   │ │                    │
   │ └─ Vision AI         │
   └──────────────────────┘
```

영상 AI처럼 무거운 연산은 FPGA의 DPU가 담당하고, 음성 검출과 시퀀스 분류처럼 상대적으로 가벼운 연산은 Cortex-A53에서 처리합니다.

### 2. 단일 DPU 자원 공유

하나의 DPU 슬롯에 Gesture 모델과 Task 모델을 번갈아 올립니다.

**동시에 실행하는 것이 아니라 시분할합니다.**

### 3. CPU 상주 웨이크워드

DPU가 `task` 모델을 실행하는 동안에도 CPU의 웨이크워드는 계속 동작합니다.

따라서 사용자는 **언제든 웨이크워드를 말해 다시 제스처 모드로 돌아올 수 있습니다.**

### 4. 상태 기반 제어

모든 음성 및 제스처 이벤트는 하나의 상태 처리 로직을 거쳐 새로운 상태를 생성합니다.

```text
입력 이벤트
    │
    ├── wake
    ├── open
    ├── bye / close
    ├── left / right
    ├── up / down
    └── zoom
          │
          ▼
   apply_event()
          │
          ▼
      새로운 상태
```

이 구조를 통해 하드웨어 없이도 주요 상태 전이를 검증할 수 있도록 구성했습니다.

## 프로젝트 목표

### 1. 손을 사용하지 않는 카메라 조작

음성으로 시스템을 깨우고 제스처만으로 카메라 화면을 제어합니다.

### 2. 단일 DPU에서 여러 AI 모델 운용

하나의 DPU 자원을 여러 AI 모델이 공유할 수 있도록 모델 교체 및 상태 전환 구조를 구축합니다.

### 3. 도메인 독립적인 시스템 구조

Gesture / Wakeword / 상태 제어와 Task AI 모델을 분리하여 **Task 모델을 교체할 수 있는 구조**를 목표로 합니다.

### 4. 엣지 환경에서의 실시간 처리

네트워크나 클라우드에 의존하지 않고 KV260 내부에서 AI 추론 및 제어를 수행합니다.
